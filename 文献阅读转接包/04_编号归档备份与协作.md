# 编号、归档、备份与协作

## 1. 仓库与目录

使用用户指定且可访问的目标仓库现有检出目录，成果放在该仓库内的 `读文献/`，避免放到仓库之外无法随Git保存。新仓库路径未指定时不硬编码旧 `/workspace/007`。云任务已隔离，未经用户明确要求不另建Git worktree。

每次独立阅读对话建立 `读文献/YYYY-MM-DD-NN/`；日期采用该次首次建档时北京时间。当天NN从01起，先检查已有目录再取未占用编号，超过99自然扩展。同一阅读对话跨日、追问或明确修订沿用其目录；新阅读对话必须新目录。

对话边界以用户说明为准。相同主题、仓库、日期、连续W编号或助手可见聊天历史均不是合并理由。只有明确属于同次续读或修订才沿用；归属不清且影响保存时先提问。读取历史清单只用于恢复身份和理解，不授权往旧目录追加。

按已确认新结构，每次N篇文献生成N＋4份Markdown：

```text
目标仓库/
  文献阅读转接包/                 # 本包6份规则；可整体复制，内部链接保留
    00_入口与执行顺序.md
    01_研究主题与任务目标.md
    02_文献阅读与NEWstudy讲解.md
    03_综述组会与错误汇总.md
    04_编号归档备份与协作.md
    05_旧规则逐条去向核对.md
  读文献/
    YYYY-MM-DD-01/               # 一次阅读对话：示例W02、W03
      README.md
      01_本次综述.md
      02_本次组会.md
      03_本次错误汇总.md
      NEWstudyW02.md
      NEWstudyW03.md
    YYYY-MM-DD-02/               # 另一次对话，另行生成自己的成果
      ...
```

这只是命名示例，不代表已经建档。两篇时恰为6份阅读Markdown，是2＋4的结果；不能误解为再次规定每次固定6份。原有五份、六份及“六份＋NEWstudy”成果结构在新仓库被本结构替代，不继续并行生成。

不按题名、方向、年份或算法另建逐篇子目录，不新增平行的literature、work/current或总综述体系。无真实文献时不创建占位目录和空笔记。历史档案保持原样，不自动拆分、移动、重命名、删除或补写。文件采用UTF-8及清晰Markdown；不以“最终版2”反复复制保留版本。

## 2. W编号

- 按文献首次上传顺序跨对话累计W01、W02……；至少两位，超过W99自然扩展。不按题名、年份、文件名或完成顺序重排。同一对话多批上传按批次先后接续。
- 一篇独立文献一个稳定编号。提示词、笔记、数据等非文献附件不占号；不因删除附件或调整顺序重新编号。
- 根据DOI、正式题名、作者、年份核实重复；重复上传或重读沿用编号、不增加独立数量。修订版和补充材料默认关联原编号并注明版本关系，不混同未经核实的不同论文。
- 新对话先读取实际可访问历史索引。旧库使用第五份清单，新库使用每次目录README。历史不可访问时可采用用户明确给出的截止编号，但身份和累计数标明核实限制。
- 无索引也无明确截止编号时先问；期间可阅读，但正式编号待确定，不用猜测W号创建正式NEWstudy。确认首次无历史建库或用户明确重建编号后才从W01开始。
- W编号跨目录累计，与对话日期分别维护。换仓库不自动重置；若用户另立编号体系，记录旧新对应以免引用混乱。
- W编号不替代完整题名和DOI；正文证据、跨篇引用、综述与错误归属均标明W编号。重读时相同NEWstudy文件名只在本次独立目录生成，不能覆盖另一对话。

## 3. 每次目录的简短索引

`README.md`负责身份、定位和恢复，替代旧第五清单。名称固定，不随W范围改名。同次新增文献更新这一份，保留记录与人工批注；不留下多个范围版本，不用范围暗示未涉及文献。

开头简记所属目录、建档/更新日期、本次涉及篇数和新增独立篇数、累计独立篇数、最大W编号、历史依据与核实状态。累计数量不能仅凭最大W号推算；记录不完整则标待核实。

主体按首次上传顺序列“W编号｜正式题名｜DOI或来源｜原件文件名/位置｜阅读状态｜NEWstudy链接”，附本次综述、组会、错误汇总链接。作者、年份、刊物、材料完整性等必要元数据可用紧凑的逐篇附注，避免无限加宽表格；可加少量主题标签帮助查找。

题名来自正文而非附件名。DOI依据原文或可靠来源，区分“未核实”“原文未提供”“不适用”；原文没列DOI不等于没有DOI。未知元数据不猜填。

简记每篇概览、深入阅读、关键证据核查、组会材料的状态：已完成、部分完成、未执行及实际缺失。收藏、已读、核查完成是不同状态，不能作论文质量等级。PDF页序与印刷页码约定可在此说明；关键定位仍写在相应解释旁。

保留重复上传、版本更新或编号修正的说明；恢复时必需的当前进度、困难和下一步以简短条目记录，不写长篇综述、教程或错误表。原文错误详表在错误汇总，普通阻塞不能假称原文错误。不在NEWstudy重复管理栏目。

相对链接定位到真实文件或章节；跨对话引用包含目录和W号。重要内容变更时检查受影响链接，避免只依赖本机绝对路径或临时附件路径。

## 4. 本地保存与GitHub

使用现有认证和仓库配置，检查已有变更并保护用户修改、有效内容和批注。每完成可独立理解的分析单元或准备结束时保存成果、更新索引状态，核对相关文件内容一致；不能假定聊天自动进入GitHub。

不同保存状态分别报告：

| 状态 | 能确认的内容 |
| --- | --- |
| 本地文件已保存 | 当前实例可读取，不代表永久可用或已在GitHub |
| Git本地已提交 | 本地有版本记录，尚不代表远程存在 |
| 已推送并核实远程 | 指定分支确有相应提交及文件，不包含未提交成果或未上传PDF |
| 环境发布已确认 | 产品确认相应环境版本；不等于GitHub保存或后台进程永久运行 |

Git提交、推送按用户已有授权范围执行，不反复请求已给过的许可；本规则本身不赋予未知新仓库写入权。换仓库需先明确目标和操作范围，不能把对旧库的授权当成对任意新库的授权。

执行时：核对目录、分支及远程；审查差异；只暂存本次相关成果；排除密钥、凭据、缓存、临时渲染和不应上传的内容；用明确提交说明提交，遵循目标分支和保护设置；推送后核实远程提交及相关文件。必要时用授权分支/PR，不伪造身份或绕过保护。

推送失败保留本地成果，说明哪些尚未远程保存；不强推、不硬重置或覆盖远程历史。冲突先保留双方内容并告知用户共同处理。已有本地修改也不能在恢复时盲目覆盖。GitHub上的修改删除会影响后续检出，不将远程视作不会变化的保险箱。

## 5. 原件、图片与格式

按用户当前提供的附件或可访问路径读取原文，记录必要来源；不擅自移动、改名、删除或上传原件。没有收到保存原件的明确要求时，不规划PDF长期存储，不创建相关待办，也不要求用户先决定原件保存方式。

需要保存的代码、表格、图像使用适当格式，不强转Markdown；只有与当次任务相关且已授权的资源才持久保存。学习稿中的必要图片要实际可访问，不能只留临时绝对路径。若需要新增资源存放约定而现有规则不足，说明必要性并询问，不默默加平行目录。未授权原始PDF入库不能因截取个别图而解释成整份上传授权。

Markdown是默认成果；Word另等用户指令。不得擅自安装插件、创建外部应用内容或同步到新平台。不能真实创建文件时说明限制，按约定文件名提供完整可复制内容，不称已经保存；不能访问原文时可处理不依赖原文的任务，不把环境恢复作为所有讨论的前提。

## 6. 新对话与环境恢复

1. 确认正确仓库、分支和实际文件状态，保护现有修改。
2. 按00读取本包前五份，不能恢复成旧提示词多套并行；规则有疑义再查05。
3. 根据历史目录索引恢复编号、身份、实际已读范围和关键阻塞，确定此次新目录或用户明确指定的续读目录。
4. 逐篇学习先读对应NEWstudy；快速回看主要关系用综述，准备汇报看组会，争议与修订看错误汇总。不能要求用户跳转才能补齐NEWstudy必要教学。
5. 核心数值、争议或新推断按需回查原文；只有笔记/摘要时说明，不声称重读全文。不可访问资料不装作已读。
6. 核对状态后继续本次工作，保留有效旧内容及人工批注。更新旧档案需有相应授权，不把另一对话新成果并入旧目录。

GitHub只能恢复实际推送的文件。已丢失且未备份的文件需从仍可访问聊天或其他备份重建，说明来源和缺失；不能承诺自动记住其他对话、附件或恢复未上传PDF。

## 7. 困难、默认设置与协作

默认关注问题、方法、实验、局限和相关项目目标；未指定汇报时长给可伸缩提纲，语言默认中文，听众按新生和课题组考虑。资料可读、身份清楚、目录已授权时直接工作，不要求逐阶段批准，也不让用户反复填写可合理确定的信息。

难题影响理解、指标、结论、文件安全或后续工作时，及时说明具体位置、已尝试什么、影响和可选处理方式并提问。不忽略、不无限独自排查；等待时推进独立部分。一般原文错误按03标注后继续，不重复让用户查勘误；需要精确复现而值未知时再提出必要问题。

不自动扩大为完整复现实验、无关基础课程、平台迁移或插件安装。自行复算、解释与实现验证分别报告；未执行的检查不称通过。用户提出状态问题时简要回答并继续原任务，除非用户明确暂停或改目标。

## 8. 规则变更与待确认事项

用户后续明确要求优先。助手提出优化必须说清改什么、为什么、影响何处并询问；未经确认不能加入生效规则。用户直接明确的新要求按授权范围落实，不需机械地再次审批。

未来提案先在本节单独列出来源/日期、现状、建议、影响、待确认问题；不能混入其他已确认条款。用户确认后再更新对应文件、入口和变更记录，通过Git保留历史。若提案较多需要独立目录，先征询，当前不建空文件夹或复制多份“最终版”。

不预设一张接入问题清单。只对当前实际任务缺少且确实影响执行的信息提问；用户已指定仓库、编号或范围时直接采用。举例、旧案例和未经采纳的助手建议不自动转为用户任务，不延续为新窗口的待确认事项。

已确认变更：2026-10-18，采用本包6份统一规则；阅读成果采用每篇NEWstudy＋每次综述、组会、错误汇总、简短索引；允许必要复用，NEWstudy不得因分工而缺少讲解；错误状态按03分别记录。

## 9. 交付报告

结束时简要给出对话目录、本次W编号和题名、实际文件链接、最重要发现与相关课题启发、真实阅读/核查状态、未解决问题及影响、累计数量/最大编号的核实状态，以及本地保存、提交、推送的实际结果。除用户要求或无法保存外，不在聊天重复贴全部正文。

不能把云端保存说成修改了用户本地电脑，也不承诺云环境永不失效。没有真实文献时只报告准备工作，不生成假笔记、假W号或假完成状态。
