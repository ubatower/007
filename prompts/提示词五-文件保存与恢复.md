# 提示词五：文件保存、GitHub备份与跨对话恢复

本文件依据用户已确认的文件分工和保存路径编写，负责文件管理、保存状态、恢复顺序及规则变更，不替代其他提示词的研究目标或阅读流程。

## 1. 适用范围与规则关系

- 提示词一负责完整研究目标和面向研究生新生的讲解要求。
- 提示词四负责分层阅读、证据核查、组会、日期对话目录及六份成果文件；提示词三补充跨对话W编号与第五份清单细则。
- 本文件适配以上已确认结构，不另设逐篇目录或总综述目录；第六份按[已确认补充要求](confirmed-additions/第六份详细阅读总结与符号说明.md)生成，旧的五文件限制不再适用。
- 每次独立阅读对话新建子目录，各存本次文献的六份Markdown；对话划分与历史错误处理以[独立建档补充](confirmed-additions/每次阅读对话独立建档.md)为准，不默认将新文献并入旧目录。
- 用户后续明确要求优先。新增要求和助手提出的优化单独记录，未经确认不并入既定规则。发生未解决的规则冲突时提问，不自行覆盖。
- 用户已确认的后续补充单独保存并从入口链接；本次错误处理按[原文错误标注补充](confirmed-additions/原文错误标注.md)执行，查无勘误后完成标注即可继续，不重复要求用户查找。
- 本文件的完善不构成Git提交、推送、环境发布或原始PDF上传授权。

## 2. 目录与命名

当前仓库为`ubatower/007`，检出目录为`/workspace/007`。阅读成果根目录已确认为`/workspace/007/读文献`。

```text
/workspace/007/
  prompts/
    README.md                         # 已确认分工、入口与准备状态
    提示词五-文件保存与恢复.md          # 本文件
    originals/                        # 四份上传原文，保留不改
    proposals/                        # 未确认提案、旧草案及审阅记录
    confirmed-additions/              # 用户后续已确认的新增要求
  读文献/
    YYYY-MM-DD-NN/
      01_阅读心得与综述.md
      02_精简主题与凝聚结论.md
      03_阅读思路与教程.md
      04_必要知识点.md
      05_本次对话的文献排序W….md
      06_详细阅读总结与符号缩写说明.md
```

- 日期采用该次阅读对话首次建档时的北京时间；新阅读对话必须新建子目录，同一次阅读对话跨日续读沿用该次目录。同日多次独立阅读对话使用不同NN。
- 每个子目录分别保存该次文献的完整六份成果，不跨阅读对话合并正文。W编号跨对话累计，与目录划分分别管理；同一仓库、主题或连续编号均不是合并依据。
- 以用户说明的阅读对话边界为准；仅在用户明确同一次对话补充、续读或修订时沿用该次目录。归属不明先提问。用户明确修订旧档案时可更新指定旧档案，但不自动将另一阅读对话的新文献归入旧目录。
- NN按当天已有目录递增，先检查再创建。没有真实文献时不创建占位阅读目录和六份空笔记。
- 01—05的名称及职责遵循提示词三、四，第六份遵循已确认补充。第五份按实际涉及的W编号命名，不能用范围暗示未涉及文献。
- 不另建`literature/notes`、`literature/index.md`或`work/current.md`等平行管理路径。
- 当前进度、关键未决问题和下一步放在当前01的疑问队列或后续行动章节；文献清单与阅读状态放在05，不在六份之外重复堆放同类阅读成果。
- 规则提案保存在阅读成果目录之外的`prompts/proposals/`，使用含义明确的主题文件名；不靠“最终版2”等复制名称保留历史。

## 3. 文献身份、编号与链接

- W编号按首次上传顺序跨对话累计；提示词、笔记和其他非文献附件不占号。重复文献核实后沿用编号。
- 建库前用户确认文献数为0，因此首次真实文献从W01开始。此为历史起点；当前编号和累计数必须读取实际第五清单，不从零重新分配。
- 未来恢复时重新检查实际历史清单，不能把上述初始状态当作永久状态。历史不可访问且没有用户明确截止编号时，先询问再正式编号。
- 正式题名、作者、年份、DOI、原始文件名和材料完整性依据实际材料填写。未知、原文未提供和不适用分别标记，不猜填。
- 导航使用仓库内相对链接。第五份清单定位01—04及06笔记中各W文献的具体章节；跨档案引用同时包含目录位置与W编号，不能仅依赖本地绝对路径。
- 更新第五份清单文件名时检查并同步受影响的内部链接，保留有效记录及人工批注，不盲目覆盖目标文件，不留下重复范围清单。

## 4. 保存内容与可恢复性

- 使用UTF-8 Markdown保存阅读分析、证据定位、必要教学解释及未决问题。内容要求以其他提示词为准，不为保存规则重复整份综述。
- 区分原文观察、作者解释、助手推断与迁移建议；保留关键条件、页码或图表公式定位，以及实际核查状态。
- 文件生成不等于阅读、证据核查、实验复现或组会排练完成。
- 原始文献保留原位置，记录来源和当前可访问路径，不擅自移动、重命名、删除或上传。
- 原始PDF的长期保存方案单独列为待确认事项。记录附件路径、题录或DOI不等于备份原文，也不保证新环境仍能访问附件。
- 聊天中的重要新增分析应更新对应的既有成果文件；不能假定聊天内容会自动进入GitHub。

## 5. 本地保存、提交、推送与环境发布

以下是不同状态，交付时据实说明：

| 状态 | 能说明什么 | 不能据此承诺什么 |
| --- | --- | --- |
| 云环境内文件已保存 | 当前实例可读取真实文件 | 永久可访问、GitHub已有文件 |
| Git本地已提交 | 本地Git记录了指定内容 | 远程已保存 |
| 已推送且远程已核实 | 指定远程分支包含相应提交与文件 | 未提交内容或原始PDF也已备份 |
| 环境发布已确认 | 产品确认相应环境版本已发布 | GitHub已推送、后台进程永久存活 |

每完成一个可独立理解的阅读或分析单元，或准备结束当前工作时，保存相关成果、更新05的状态及01的未决问题，检查六份文件之间是否一致。

只有已获用户授权时才执行提交与推送：

1. 在`/workspace/007`确认当前分支、工作区变化及原有用户修改。
2. 检查本次差异，排除密钥、凭据、临时缓存及不应上传的内容；只选择本次相关文件，不盲目提交整个工作区。
3. 按当前Git身份与仓库约定提交，说明本次实际变更；不伪造身份，不绕过仓库保护规则。
4. 使用已授权目标分支和现有认证推送，再核实目标远程分支的提交以及文件确已包含其中。只有快照相同不能证明尚未提交的文件已备份。
5. 失败时保留本地成果，说明阻塞和哪些文件尚未远程保存。冲突先保留双方内容并提问，不强制推送、硬重置或覆盖历史。

环境发布由产品界面完成，不能把“保存草稿”“脚本执行成功”或“环境正在运行”等同于发布成功。若界面显示无法确认发布状态，保留工作并依提示返回开始设置的客户端核实，不自行宣称成功或失败。

## 6. 新对话或新云环境的恢复顺序

1. 确认可以访问正确仓库与目标分支；使用现有检出目录，不覆盖本地修改。云任务本身已隔离，未经用户明确要求不创建Git worktree。
2. 阅读`prompts/README.md`与本文件，了解已确认分工和未决事项；再读取适用的提示词原文，不将提案或旧目录示例当作生效规则。
3. 查找`读文献/`中实际存在的第五份清单，根据W编号、正式题名、DOI及用户指定任务恢复历史。读取历史清单不代表向旧目录追加；新阅读对话先确定新子目录。无法确定对话归属或用户指定的续读档案时先提问，不仅凭日期、编号或可见上下文猜测。
4. 先读对应02恢复主题、结论、课题关联和边界，再读01恢复证据、论证、疑问与下一步；需要时读03教程或组会材料、04基础知识、06详细总结与符号缩写。
5. 涉及关键数值、争议或新推断时，按需回查原文。只有笔记或摘要时明确说明，不宣称已经重新阅读全文。
6. 检查W编号、文件状态和待办后继续增量工作，保留有效旧内容及批注。

不存在历史文件时如实说明。GitHub只能取回实际已推送的内容；未推送且已丢失的文件需从其他备份或仍可访问的聊天恢复，并注明缺失和来源。PDF不可访问时可先处理不依赖原文的新任务，不能把待核实结论升级为已核查。

## 7. 困难提问与规则变更

- 遇到影响方法理解、关键证据、指标口径、课题判断、文件安全或后续工作的困难，及时向用户说明：具体位置、问题、已尝试方法、影响和建议选项。
- 不跳过核心障碍，不反复进行没有新依据的排查；无法继续推进时向用户提问，等待期间继续不受影响的工作。
- 阅读疑问保存在01，编号和身份问题同时体现在05。没有真实文献时，准备阶段问题记录在`prompts/README.md`。
- 新增要求、助手优化与未决方案保存在`prompts/proposals/`，说明来源、改动理由、影响范围和待确认问题，不直接修改已确认规则。
- 用户明确确认某项后，只应用获批范围并更新入口；部分确认不等于整份草案批准。涉及Git推送或外部应用的执行授权单独核实。
- 保留原始提示词。重要修正说明理由，未解决冲突明确保留，不静默覆盖人工批注。

建库初始状态仅为历史依据。当前已进入真实阅读阶段，最新编号、阅读进度和保存状态应查看入口及实际第五清单；原始PDF长期保存方案仍待确认。
